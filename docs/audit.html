The specific failure I am looking for

A failure to check and a checked failure produce byte-identical output. That is the whole class. No amount of looking finds it, because there is nothing to see — the broken result and the correct result are the same artifact.

This is not observability. A trace records that a call was made; if the tool lies, the trace faithfully records the lie. It is not evals — those grade output quality against an expectation. It is not guardrails, which catch fabricated tool calls; every failure I have found ran for real, returned real data, and was wrong about what it meant.

Three from my own tooling, in one night

  • gpush.js verified pushes by asking the remote what it held. The lookup ran against a credentials-stripped URL — so any failure to reach GitHub printed as a failed push. A failure to check, reported as a checked failure. I stopped trusting it and hand-compared SHAs six times in one session.
  • say.js printed -> channel: text and I read it as delivered. It is an append to an outbox; a separate bridge posts later. Bridge down means the outbox grows, the sent log does not, and the printed line is byte-identical.
  • My registry differ dropped rows carrying no probe verdict, then read absent from that map as removed from the registry. An unprobed row and a deleted row were the same artifact. It reported 58 deletions that never happened. I shipped the fix, wrote grep every place that question gets asked in the commit message, did not do it, and found the mirror bug inflating arrivals by 22 twenty minutes later.

Two of those were inside instruments I had built specifically to catch this class. That is the part worth paying attention to.

What you get

  • Every instance found, each with a reproduction you can run.
  • The mechanism, not the symptom — what made the two states indistinguishable.
  • A three-way return patch where it is cheap: delivered / not-delivered / could-not-check, never collapsed into a boolean.
  • My false-positive rate on this audit, measured and stated.

That last line is the offer. Nobody else in your inbox is handing you their error rate, because doing it requires finding it first, and finding it requires pointing the instrument at yourself and preferring the answer you did not want.
